# Double Pendulum Lab

RustとWebAssemblyで物理計算を行い、ブラウザのCanvasへ描画する二重振り子シミュレーターです。摩擦と空気抵抗のない理想モデルを、固定刻みの4次Runge–Kutta法で計算します。

ディレクトリ構成と各モジュールの詳細は [`ARCHITECTURE.md`](./ARCHITECTURE.md) を参照してください。

## 機能

- 3台それぞれの質量 `m1`・`m2`、腕の長さ `l1`・`l2`、初期角度 `θ1`・`θ2` の設定
- 任意の小数を直接入力でき、上下スピナーでは `0.01` ずつ調整可能
- 3台の独立した二重振り子の同時アニメーション
- 色分けされ、新しい部分ほど明るくなる各第2質点 `m2` の軌跡
- 選択した振り子の `m1`、`m2`、系全体のエネルギーを示す時系列グラフ
- スタート、一時停止・再開、リセット
- 複数の独立した二重振り子を同時に扱える物理エンジン

## 物理モデル

2本の腕は質量のない剛体とし、各腕の先端に質点を置きます。固定支点を原点として、角度は下向き鉛直から測る絶対角です。

- 重力加速度: `9.80665 m/s²`
- 初期角速度: `ω1 = ω2 = 0`
- 数値積分: 4次Runge–Kutta法（RK4）
- 時間刻み: `1/240 s`
- 位置エネルギーの基準: 両方の腕が真下にある状態

## シミュレーション精度

現在の実装は、倍精度浮動小数点数（`f64`）と固定刻み `1/240秒` の4次Runge–Kutta法を使用しています。通常のパラメータによる教育・可視化用途では十分な精度がありますが、科学計算として長時間後の軌道を保証するものではありません。

### デフォルト条件でのエネルギー誤差

以下のデフォルト条件を使用し、初期値に対する合計エネルギーの最大相対誤差を測定しました。

```text
m1 = m2 = 1 kg
l1 = l2 = 1 m
θ1 = 170°
θ2 = 120°
ω1 = ω2 = 0 rad/s
```

| シミュレーション時間 | 最大相対誤差 | パーセント表示 |
|---:|---:|---:|
| 1秒 | `6.1 × 10⁻⁷` | 約0.000061% |
| 10秒 | `9.6 × 10⁻⁷` | 約0.000096% |
| 60秒 | `6.4 × 10⁻⁶` | 約0.00064% |
| 300秒 | `2.8 × 10⁻⁵` | 約0.0028% |

この条件では、少なくとも数分程度のエネルギー保存は良好です。ただし、RK4はエネルギーを厳密に保存する積分法ではないため、長時間計算では徐々にドリフトします。

### 軌道の予測精度とカオス

時間刻みを `1/3840秒` まで細かくした計算を基準として比較すると、現在の `1/240秒` の状態差は1秒後で約 `5.6 × 10⁻⁶`、5秒後で約 `2.5 × 10⁻³` でした。10秒後には軌道が大きく異なる状態まで発散しました。

これはエネルギー誤差だけの問題ではなく、二重振り子が初期値や数値誤差に非常に敏感なカオス系であることによります。合計エネルギーがよく保存されていても、長時間後の角度や位置が高精度な基準解と一致するとは限りません。現在の実装は運動の定性的な観察には適していますが、長時間後の位置予測には適していません。

### 極端な設定での精度不足

画面から入力できる範囲には、固定刻み `1/240秒` では変化を十分細かく追えない条件も含まれます。デフォルト角度のまま10秒間計算した結果は次のとおりです。

| 条件 | 最大合計エネルギー相対誤差 | 評価 |
|---|---:|---|
| `m1=m2=1 kg`, `l1=l2=1 m` | 約 `9.6 × 10⁻⁷` | 良好 |
| `m1=m2=1 kg`, `l1=l2=0.01 m` | 約37% | 時間刻みが不足 |
| `m1=m2=1 kg`, `l1=0.01 m`, `l2=1 m` | 約0.26% | 精度低下 |
| `m1=0.01 kg`, `m2=100 kg`, `l1=l2=1 m` | 非有限値まで不安定化 | 計算継続不可 |

腕が短いほど固有周期が短くなり、同じ1秒間により速く状態が変化します。また、極端な質量比では大きな角加速度が発生する場合があります。このような条件では固定刻みを細かくするか、誤差に応じて刻み幅を変更する適応刻み法が必要です。

描画は通常約60 Hzですが、物理計算は240 Hzで独立して実行されるため、通常の描画フレーム変動は積分精度へ直接影響しません。ただし、ブラウザが0.1秒を超えて停止した場合は追従ステップ数を制限しており、シミュレーション時間が実時間より遅れます。

## 構成

- `src/`: Rust製の物理エンジンとWasm公開インターフェース
- `docs/`: GitHub Pagesで公開するHTML、CSS、JavaScript、Wasm生成物

物理エンジンは3台の振り子を安定したIDで管理します。初期条件、描画データ、軌跡、エネルギー履歴もIDごとに分離されています。

## ビルド

[Rust](https://www.rust-lang.org/tools/install) と [wasm-pack](https://rustwasm.github.io/wasm-pack/installer/) が必要です。

```sh
cargo test
./build-pages.sh
```

`build-pages.sh` はWasmを生成した後、`wasm-pack` が作る除外設定を削除します。`docs/pkg/` はGitHub Pagesが直接読み込むため、生成されたJavaScriptとWasmもGitへ追加してください。

ビルド後、リポジトリのルートで静的HTTPサーバーを起動します。

```sh
python3 -m http.server 8000 --directory docs
```

ブラウザで `http://localhost:8000` を開いてください。Wasmはローカルファイルとして直接開けないため、HTTPサーバー経由で実行します。

## GitHub Pages

リポジトリのPages設定で公開元をデフォルトブランチの `/docs` に指定してください。`docs/pkg/` を含むビルド済みファイルをコミットすれば、そのまま静的サイトとして配信できます。

## テスト

```sh
cargo test
```

真下静止状態、位置とエネルギー、RK4の更新、長時間計算時のエネルギー誤差、複数振り子の独立性とID安定性を検証します。
